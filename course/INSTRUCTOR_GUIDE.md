# Instructor Guide

## Suggested 90–120 minute session
- 10 min: introduce the problem and users
- 15 min: explain concepts and folder structure
- 20 min: demonstrate one feature
- 25 min: students build or modify
- 15 min: testing/debugging
- 10 min: reflection and extension

## Preparation
Run every sample on a clean environment, check the current installation commands, prepare expected-output screenshots, use fictional data, and provide an offline path for API labs. Maintain a known-good copy.

## Common misconceptions
- Saving a file is not the same as running an application.
- Starting successfully does not prove all features work.
- The active terminal may use a different Python interpreter.
- Frontend validation does not replace backend validation.
- localStorage is not a secure or shared database.
- AI-generated answers may be incorrect.
- API keys must not be put in client-side JavaScript or source control.
- Flask development server is not production hosting.
- Happy-path tests do not cover boundary and recovery cases.

## Assessment checkpoints
After Lab 3, students should validate data and persist it. After Lab 5, they should explain request/response and database CRUD. After Lab 8, they should distinguish application logic from generated model output. After Lab 11, they should reproduce a project from its README.

## AI and academic integrity
Permit AI as a learning aid. Ask students to keep a prompt log, explain two functions, demonstrate a failure and fix, and identify one AI suggestion they verified independently. Follow institutional rules for attribution.

## Accessibility
Use plain-language errors, keyboard-friendly controls, readable contrast, written steps and flexible time. Offer offline exercises using mock responses.
