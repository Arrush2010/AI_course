# Reusable AI Prompt Library

Never paste secrets, API keys, passwords or confidential data.

## 1. Requirements
Act as a product analyst. Convert this idea into target user, problem statement, user stories, measurable acceptance criteria, assumptions, non-goals and risks. Keep the first version achievable in [TIME].

## 2. Plan before code
Plan [PROJECT] for a beginner using VS Code. Recommend a simple stack, explain why, show the folder tree, dependencies, exact run commands, tests and security considerations. Do not generate code yet.

## 3. Generate complete files
Implement [FEATURE]. Give complete contents for every new or changed file with exact paths. Do not use unexplained placeholders or omit sections. Include setup commands, sample input/output and tests.

## 4. Explain code
Explain this code to a beginner: purpose, important lines, variables, sample execution, assumptions, likely errors and a small modification exercise. [PASTE CODE]

## 5. Debug
OS: [OS]. Command: [COMMAND]. Expected: [EXPECTED]. Actual: [ACTUAL]. Full error: [ERROR]. Relevant code: [CODE]. Diagnose causes in order, give the smallest safe fix and a verification test. Do not claim it works until I test it.

## 6. Generate tests
Create tests for normal cases, boundary values, invalid input, empty data, missing files and recovery. Include setup, action and expected result. Use [FRAMEWORK]. Do not alter code merely to make tests pass.

## 7. Review code
Review correctness, readability, duplication, validation, errors, security, tests and documentation. Rank findings by severity, name exact files/functions, and propose small fixes with regression tests.

## 8. Security review
Check credential exposure, unsafe rendering, injection, weak validation, permissions, file handling and sensitive logs. Explain fixes and state what cannot be verified. Do not ask for real secrets.

## 9. Refactor safely
Refactor [FILE] for readability without changing behavior. State intended changes, provide complete changed files and regression tests, and explain the result.

## 10. README
Create a README with purpose, features, requirements, structure, setup, configuration, run commands, sample usage, tests, data/privacy notes, limitations and troubleshooting. Ensure commands match the project.

## 11. Git coach
Teach me to inspect status, review changes, commit logical changes, read history and recover a local mistake. Explain commands first. Warn before destructive commands; do not casually recommend force push.

## 12. Capstone
Help build [IDEA] in stages: requirements, MVP, architecture, data model, tests, one feature at a time, review, documentation and demo. Ask me to confirm requirements before implementation.

## 13. Verify AI output
List technical claims needing verification and show how to check each using official documentation, local commands or tests. Distinguish facts from assumptions.

## 14. Hint mode
Do not reveal the full solution immediately. Give one hint at a time, ask me to predict behavior, then let me try. If wrong, explain the misconception and suggest a minimal correction.

## 15. Offline mode
Design an offline version of [PROJECT] using fixtures or mocked responses. Clearly label simulated behavior and provide repeatable tests. Never imply mock output is live data.
