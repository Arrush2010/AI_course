# Instructor Reference Expectations

Alternative implementations are acceptable when requirements, tests, readability and safety are satisfied.

1. Calculator: four operations, repeated menu, invalid-input handling, zero-division protection.
2. Marks: unique IDs, marks 0–100, correct totals/averages, documented grading thresholds.
3. Expense tracker: CSV persistence, ISO dates, positive Decimal amounts, accurate monthly totals.
4. To-do: CRUD, filters, counts, localStorage, safe text rendering.
5. Registration: Flask routes, SQLite, server validation, parameterized SQL, persistent records.
6. Dashboard: validated data, filter-consistent KPIs/charts, empty-state handling, filtered download.
7. API: timeout and HTTP errors in live implementation, response validation, mock tests, no embedded secrets.
8. AI study: mock mode, provider adapter, input limits, graceful errors, model output treated as untrusted.
9. Reports: validated input, accurate summaries, escaped HTML, separate output files.
10. Inventory: relational data, transaction-safe stock changes, nonnegative stock and rollback on failure.
11. Release: reproducible setup, tests, `.gitignore`, secret handling, smoke test and rollback plan.
12. Capstone: scoped requirements, maintainable code, meaningful tests, reproducible setup, documented limitations and student explanation.
